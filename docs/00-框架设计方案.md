## 0. 定位与边界

**合法性边界**：所有投注标的均为中国体育彩票竞彩足球官方在售场次（sporttery.cn），玩法限定胜平负，场次限定五大联赛。**境外公开平台的赔率数据（如懂球帝聚合的欧美公司赔率）仅作为分析参考源接入，绝不作为投注标的**——参考其赔率结构与市场共识，投注动作只发生在体彩。

**现实约束（系统价值观，不可省略）**：
- 竞彩足球返奖率约 73%，随机投注长期期望约 **-27%/注**，任何策略工具都无法改变抽水结构。
- 工具目标优先级：①纪律化（强制预算与复盘）②信息整合 ③负 EV 过滤（识别并放弃明显不值的投注）④信号捕捉（赔率变动反映的精算与资金意图）。
- 赔率异动是**概率信号**而非确定性内幕，爆冷不可消除。输出永远是"概率+理由"。

**数据源**：主源为体彩官方 webapi（2026-10-30 两项实测通过，含二次实测新发现，见第 12 节）；参考源为懂球帝聚合赔率（v0.2 接入）。

## 3. 核心数据结构（`jc/models.py`）

```python
@dataclass
class Match:
    match_id: str          # 官方 matchId（数字，全局唯一，主键）
    match_num: str         # 展示编号 "周五003"
    league: str            # 英超/西甲/意甲/德甲/法甲
    league_id: int|None
    home: str; away: str
    home_rank: int|None    # 解析自 '[英超2]' 格式
    away_rank: int|None
    match_time: datetime
    single_sellable: bool|None   # poolList[HAD].single==1
    status: str            # Selling / Finished / ...

@dataclass
class Odds3Way:
    match_id: str
    ts: datetime           # 优先取官方 had.updateDate+updateTime，缺失时用抓取时刻
    win: float; draw: float; lose: float
    goal_line: str|None            # 让球数（存而不用）
    hhad_win/draw/lose: float|None # 让球三向（存而不用）

@dataclass
class Prob3:               # home/draw/away，Σ=1
@dataclass
class Signal:              # kind / side(win|draw|lose) / strength(0~1) / detail(人话)
@dataclass
class Leg:                 # match+side+odds+market_prob+model_prob+edge+signals
@dataclass
class Bet:                 # legs(1条=单场,N条=N串1) + stake_bets
@dataclass
class Portfolio:           # 稳健/平衡/进取；total_bets / hit_prob / ev / max_payout / ruin_prob / rationale
```

**spec 机制**（响应 D12）：每个数据源一个 JSON 文件（端点、参数、请求头、成功判据、列表路径、字段映射、单关标识定位）。解析器是通用代码；接口变了改 spec（或由 LLM 重新生成 spec），**代码不动**。spec 内记录 `verified_at`，失效时 healer 携带报文+错误让大模型产出新 spec，人工确认后生效。

## 5. 策略层算法要点（v0.4 实现）

1. **候选腿**：每场取 edge 最大方向，`edge ≥ 3%` 入围；无合格腿则该场不出腿（**不投也是策略**）。
2. **组合空间**：单场、2串1、3串1、4串1 及官方多串模式（4串5=10元、4串6=12元等，均 ≤15 元预算内；"四串三"并非官方过关方式，落地以官网过关表为准映射最接近模式）。每组合计算联合命中概率 `Πp_i`、组合赔率 `Πo_i`、`EV`、全损贡献。
3. **注数分配**：整数注在组合间分配，总投入 ≤15 元；单组合 ≤ 总预算一半（防梭哈）。
4. **Kelly 作参考不作分配**：`f*=(p·o−1)/(o−1)` 判定"值不值得下"，分配离散化为整数注。
5. **可解释性硬要求**：每条腿必须附信号摘要（如"主胜赔率 2.65→2.10 持续走低"），无理由不出腿。

## 7. 每日运行流程

```
全天     autopoll 每 30 分钟一次（Windows 计划任务调用，或 jc watch 常驻）：
         ├─ 新场次发现：只入库新挂出的场次与初赔
         │   （应对"临开售才挂出"的比赛——体彩开售不保证提前，
         │    实测存在当天中午才挂出、当晚开赛的场次）
         └─ 全量快照：仅当按节奏到期——基础 4h；
             任一在售场次进入开赛前 8h 窗口 → 2h
17:00    analyze + recommend --bets 7（预算15元）
         └─ 生成 reports/YYYY-MM-DD.md（场次/信号/三方案/理由/风险栏/预算确认栏）
次日      settle（v0.3）→ stats 累积（v0.5）
```

官方仅给"当前赔率"，历史靠快照自建——每条赔率自带官方最后调整时间戳，轨迹时点精度不受轮询间隔限制。调度状态（上次全量时间）持久化在 `collector_state` 表，进程重启/断电不丢节奏。

## 9. 关键设计决策（已确认）

| # | 决策 | 定稿值 | 说明 |
|---|------|--------|------|
| D1 | 玩法 | 仅胜平负（不让球） | 让球数据照存，v2 可启用 |
| D2 | 联赛 | 五大联赛白名单（leagueId：英超25/西甲62/意甲40/德甲37/法甲32，按名称过滤为主） | 可配置 |

| D5 | 快照节奏 | **基础 4h；任一在售场次开赛前 8h 内加密至 2h** | 2026-11-02 用户更新（原为固定 90~120min） |
| D6 | 预算 | **单次 ≤15 元（≤7 注），1注=2元** | 用户确认 |
| D7 | 概率模型 v1 | 去水隐含概率 + 轨迹信号修正（±8pp 上限） | v2 见 D11 |
| D8 | 报告与交互 | **无前端页面**（如未来确需可视化，列入 ≥v2.0 远期再议）；Markdown + CLI；17:00 固定生成 | 2026-11-02 用户确认 |
| D9 | 历史冷启动 | 自建快照积累；第三方回补 v2 再议 | 官方 updateTime 缓解但不消除冷启动 |
| D10 | 技术栈 | Python 3.11 / SQLite / 纯标准库 | 零依赖零运维 |
| D11 | xG 回归模型 | v2：两队预期进球 → 泊松分布 → 比分矩阵 → 胜平负概率，与市场概率融合 | 用户提出，先跑通流程 |

| D13 | 测试策略 | **每个版本交付完整 unittest 套件并刷新；`jc selftest` 一键回归** | 用户提出；fixtures 用真实报文裁剪，不打网络 |

## 11. 风险与不确定性
